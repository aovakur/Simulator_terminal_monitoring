# Симулятор устройств — Быстрый старт

## 📋 Пул UID

Симулятор использует **фиксированный пул из 1000 UID** в файле `uid-pool.json`.
При запуске берутся первые N UID из этого списка (N = `deviceCount` в конфиге).

## 🚀 Запуск симулятора

### Вариант 1: С 10 устройствами (для тестирования)

```bash
cd c:\GIT_REPOS\TCM\client\simulator
npm run start:10
```

### Вариант 2: С 100 устройствами

```bash
cd c:\GIT_REPOS\TCM\client\simulator
npm run start:100
```

### Вариант 3: С 1000 устройствами (все UID из пула)

```bash
cd c:\GIT_REPOS\TCM\client\simulator
npm run start:1000
```

## ⚠️ Важно!

**Перед запуском симулятора убедитесь, что сервер запущен:**

```bash
# В другой консоли запустите сервер
cd c:\GIT_REPOS\TCM\ApiServer
npm start
```

Сервер должен слушать на порту **3005** (или измените `serverUrl` в `simulator-config.json`).

## 📊 Что происходит при запуске

1. Симулятор создаёт N уникальных устройств
2. Каждое устройство получает:
   - Уникальный `uid` (UUID v4)
   - Уникальный `device_id` (sim-device-00001, sim-device-00002, ...)
   - Отдельные папки `in/` и `out/`
3. Устройства подключаются к серверу пакетами (batch)
4. Каждое устройство отправляет DeviceStatus
5. Устройства готовы принимать файлы и команды от сервера

## 🛑 Остановка

Нажмите `Ctrl+C` в консоли

## 📁 Где смотреть результаты

```
simulator/devices/
├── sim-device-00001/
│   ├── in/          # Сюда попадают полученные файлы
│   └── out/         # Отсюда можно отправлять файлы
├── sim-device-00002/
│   ├── in/
│   └── out/
└── ...
```

## 🐛 Если что-то не работает

### Ошибка подключения
- Проверьте, что сервер запущен
- Убедитесь, что порт правильный в `simulator-config.json`

### Ошибка модулей
```bash
cd c:\GIT_REPOS\TCM\client\simulator
npm install
```

### Проблемы с путями
Запускайте скрипт только из директории `simulator/`
